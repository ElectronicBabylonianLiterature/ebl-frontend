## Findings

**B1 — Standing review.** Fabdulla1's latest review asked for 8 changes. At `7c5a04cc`: sidebar saves use `enqueueSave` (`Info.tsx:44`), `ChapterImport` Save has `disabled={disabled}`, annotation writes are queued, uncached corpus reads forward their signal, `mapSeries.test.ts` exists, `fragmentPrefetch`/`fragmentRepositoryInfo` are in `fullyCoveredPaths`, the three named suppressions are gone, and both Sass partials end in a single newline. The review stays the decision until it's redone.

**M1 — Hidden save errors.** `CuneiformFragment` has one `SupersedableOperation` for all saves, and `handleSave` starts a new token on every call. Superseding makes sense for successive writes of the same thing, but here it also hides the error of an unrelated earlier write. `EditorTabs` gets `disabled={saving}`, but `Info` stays interactive, so a genre save can queue behind a pending References save. If the References save fails, its `onError` is stale. The genre save succeeds and clears `isSaving`. The user sees no error, and the fragment on screen lacks the change. Edition, named-entity, script and date callers handle the returned promise's rejection themselves, so they're safe. Colophon and Scopes aren't, and their `async` wrappers also drop the promise.
